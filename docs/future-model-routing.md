# Future Model Routing

Status: POST-MVP DESIGN ONLY

devflow MVP must remain a deterministic unified-diff runner. It must not call Codex, Gemini, Claude, Copilot, Ollama, or any other model provider from the active execution path.

Future model routing should be introduced only after the file/git/report safety loop is reliable.

## Future Roles

- planner: decomposes goals into plans and tasks
- context_builder: selects relevant files, symbols, summaries, and recent failures
- coder: drafts unified diffs
- reviewer: checks correctness, risk, and architecture fit
- tester: writes or updates tests
- verifier: runs deterministic checks
- summarizer: updates reports, architecture notes, and handoff state
- router: selects the worker role/model/tool for a bounded job

## Routing Principles

- Models are workers, not the source of truth.
- Task Markdown remains canonical task state.
- plan.json remains a secondary index.
- Reports remain the audit trail.
- All model output that changes code must become a unified diff.
- devflow must validate, preview, apply with approval, verify, and rollback independently of which model generated the diff.

## Local Worker Policy

Local models may be used by peer orchestrators for bounded worker jobs:

- propose a patch
- explain a failure
- repair a test
- summarize context

Local models must not mutate the repo directly. They should return artifacts to the owning orchestrator, which then records them in task files and runs devflow safety gates.

## Activation Criteria

Before adding active model calls:

- task ownership is reliable
- reports are auditable
- rollback behavior is proven
- protected path policy is enforced
- dirty-worktree behavior is proven
- generated patches are validated through the same unified-diff path as human-authored patches
